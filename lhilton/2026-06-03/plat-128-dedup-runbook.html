Production Runbook
PLAT-128 · Ops Cleanup

Dedup runaway-import contacts — Sun City Welding

Soft-delete ~49k duplicate contacts for organization 107 using contacts:deduplicate-runaway-import. Reversible, dry-runnable, org-scoped.

⚠️
Destructive run (soft-delete). Always run --dry-run first and confirm the summary matches the preview below. The command soft-deletes only — fully reversible via the per-run rollback recipe.

Context

A runaway Filament CSV import on June 2, 2026 created ~49k duplicate Contact rows for Sun City Welding (org 107). The failing import row retried non-idempotently, re-creating the same handful of name groups thousands of times.

The PLAT-128 command (app/Console/Commands/DeduplicateOrganizationContacts.php, PR #7021) collapses each (first_name, last_name) group inside the affected import window down to the earliest copy (MIN(id)) by soft-deleting every later copy that owns no real activity. Copies that own real child-table activity are reported — never deleted — for manual Merge* review.

Parameters

OptionValueWhy
--organization107Sun City Welding (PLAT-128)
--min-id2998664First org-107 contact created June 2. May 30 ended at id 2,966,854; org 107 created nothing June 1 — so this is the runaway window's PK lower bound (timezone-proof).
--chunk2000Default. ~49k losers → ~25 chunks.

Why a PK bound, not a date: pre-existing real contacts (id < 2998664) are never touched. Setting min-id a little low is safe (legit singletons are preserved); too high would miss dupes. 2998664 is the safe, correct lower bound.

Replica preview — the dry-run on prod should roughly match

  • Distinct name groups / survivors kept: 1,266

3Post-run

  1. The command prints the run file path (storage/app/contact-dedup/org-107-YYYYMMDD-HHMMSS.jsonl) — the per-run audit trail of every soft-deleted id. Copy it off the server and attach to PLAT-128.
  2. Reindex search — trashed dupes still appear in the index until reindexed (global, not org-scoped; coordinate timing):
php artisan mirror:reimport && php artisan mirror:reindex

Rollback — this run only

The command prints the exact recipe with the run's timestamp. It is a timestamp-scoped restore — run via php artisan tinker on the app server:

Contact::withTrashed()
    ->where('organization_id', 107)
    ->where('deleted_at', '<run timestamp the command printed>')
    ->restore();

Re-derive min-id (only if dry-run looks wrong)

Run against the production DB (read replica or read-only SQL). Finds the runaway window's first id:

SELECT DATE(created_at) AS d, COUNT(*) AS n, MIN(id) AS min_id, MAX(id) AS max_id
FROM contacts
WHERE organization_id = 107
  AND created_at >= '2026-05-30 00:00:00'
GROUP BY DATE(created_at)
ORDER BY d;

--min-id = the min_id of the first runaway day (the June 2 burst). On the replica that is 2998664.

Safety notes (enforced by the command)

  • Soft-delete only (deleted_at stamp). Reversible; child rows stay attached; per-model delete side effects (audits, conversation-relink hook, ContactDeleted event) are deliberately bypassed.
  • Activity guard: any loser owning a row in ~44 child tables (+ notes morph, student_referrals) is excluded from deletion and reported.
  • Blank-name hard-stop: aborts if any window contact has a blank first/last name (0 here, so it won't fire).
  • Write-ahead run file per chunk → idempotent; safe to re-run after an interruption.
  • Scope is organization_id = 107 + id >= 2998664 on every query. No other org is touched.

Verification

The dry run is the verification gate: confirm survivors ≈ 1,266, losers ≈ 49,059, blank names = 0, then do the real run. After the real run, confirm the live window count dropped:

SELECT COUNT(*) FROM contacts
WHERE organization_id = 107 AND id >= 2998664 AND deleted_at IS NULL
  AND first_name IS NOT NULL AND TRIM(first_name) <> ''
  AND last_name  IS NOT NULL AND TRIM(last_name)  <> '';

Expected ≈ the "Expected live (non-trashed) window count after run" from the command's summary table (survivors + excluded).
