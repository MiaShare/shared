TL;DR

PLAT-7 is an engineering platform refactor whose PRD explicitly puts all UI out of scope, and it shipped with zero intended visible change — which is exactly what we observe. The perceived “UX gap” is an expectation/scope mismatch, not a delivery failure:

  • The forms UX leadership can actually point to is live — it shipped separately in January as PRAX-713 (“Embedded link” option + “Get Started” button).
  • The richer separate “Lead Form” UX (PRAX-708) was intentionally cut, not built — cancelled and superseded by PRAX-713.
  • The only genuine in-scope UI miss is an unwired form_context Filament filter (PRD 6 success criterion) — cosmetic, since no surface reads the column yet.

The fix is communications, not code.

5 · Why leadership perceives a UX gap (the actual problem to fix)

  1. The ticket title oversells. “Classic Website Forms” reads like a shipped end-user feature; the body is a backend domain refactor. Title ≠ scope.
  2. The prototype links are wrong. Both PLAT-7 “prototype” links point at phone-number-management. Anyone opening them expecting “the forms we built” sees an unrelated feature and concludes the prototype doesn’t match delivery.
  3. A rich UX spec exists but was cut. PRAX-708 reads like a committed feature. Comparing shipped work to PRAX-708 shows everything missing — but PRAX-708 is Duplicate, superseded by the narrower PRAX-713 (which did ship).
  4. Label collision. The builder’s “Lead Capture Form” card (rules-vs-AI) is easily mistaken for PRAX-708’s “Lead Form”.

6 · Bottom line

  • Pure UX/UI delivery gap vs PLAT-7’s own PRD: essentially none. The PRD’s UX target was “no visible change / pixel-identical”, and that is what shipped. The only in-scope miss is the unwired form_context Filament filter (PRD 6), which is cosmetic while the column is unconsumed.
  • The forms UX leadership can actually point to is live — PRAX-713’s “Embedded link” option + “Get Started” button, shipped Jan 2026, independent of PLAT-7.
  • The separate “Lead Form” UX (PRAX-708) was intentionally not built — cancelled and replaced by PRAX-713.
  • Recommended remediation is communications, not code:
    1. Fix or remove the off-topic prototype links on PLAT-7.
    2. Retitle/relabel PLAT-7 as the platform refactor it is.
    3. Explicitly mark PRAX-708 superseded and point stakeholders at PRAX-713 (shipped) so delivery is no longer measured against a cut spec.
    The one optional code item is wiring the form_context Filament filter to satisfy the PRD 6 success criterion.
